# HANDOVER

## Set up and verify (≈1 minute)
`pip install -r requirements.txt` then `pytest phase6_testing algorithm_lab -v` from the repo root. Expect 71 + 8 passed.
All runs are seeded (42) and deterministic. Tests read pre-generated JSON (`domain_results.json`, `HARDWARE_EXECUTION_MANIFEST.json`,
`vqe_adapter_run_result.json`); regenerate with the scripts in the README if you change inputs, and re-run the tests.

## Decisions worth knowing
- **Certification gate:** `HARDWARE_VERIFIED` only with `is_real_hardware=True` **and** a provider job id; simulator output can only be `SIMULATOR_VERIFIED`.
- **Honest capability marking:** unavailable adapters report why and refuse to execute; they never mock success.
- **Determinism:** SHA-256 over canonical JSON; virtual clock in the network workload; no wall-clock in hashes.
- **Replay:** append-only hash-chained log; `replay()` verifies the chain, ignores order, rejects tampering.
- **Retry policy:** rotates to the *next* node each attempt. If every node drops once, 3 attempts fail (tested and documented); use `max_attempts > len(nodes)` for transient loss.

## Known weak spots
1. QAOA gives no lift on the optimal decision vector for slack-bit knapsack problems (VANA 1.02×, AIAIC 0.76×). Consider unbalanced penalisation or slack-free encodings before investing further.
2. Bharat Mala uses a surrogate QUBO; Marine routing is only 3 waypoints (9 qubits).
3. QAOA circuits transpile to depth ~80–830 on generic device models — too deep to expect meaningful NISQ results; start hardware with Bell/GHZ.
4. Device models and noise numbers are assumptions, not calibration data.
5. O2 VQE error ≈ its spectral gap (near-miss).
